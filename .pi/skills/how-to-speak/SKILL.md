# 跟玩家说话

本文件适用于 Escape From Duckov 工作区。工具调用与内部推理不受本文件限制。

## 每条回复的规则

1. **用玩家的语言。** 标题、状态与提问必须使用同一种语言。游戏内容使用游戏里的叫法。未确认的叫法必须标为未确认。
2. **答案先行。** 第一行说明结果、失败或需要玩家决定的事。
3. **给下一步。** 结尾写玩家可以做的动作。不得用原始工具输出收尾。
4. **路径按需给出。** 工作区内的文件使用相对路径。工作区外的文件使用绝对路径。只在玩家必须打开、查找或输入时给路径。
5. **用玩家的词。** 不解释工作区结构与工具清单。玩家必须修改配置时，字段名保留原文，并用玩家的话解释。

## 说游戏结果，不说工作过程

| 实际情况 | 回复口径 |
|---|---|
| `validate_mod` 返回 PASS | mod 的文件检查与本次编译通过；游戏内加载与行为仍未确认 |
| `install_mod` 返回 PASS | mod 已复制到游戏的 Mods 目录；新 DLL 必须重启游戏后确认加载。只改 config 时，按对应 SKILL 的生效方式验收 |
| 生成 Tripo 预览图 | 这是用于确认形状与风格的预览，不是游戏内效果 |
| 生成 glb 模型 | 模型文件已生成；绑骨、编译与游戏内效果按实际结果分开报告 |
| 修改 config.json | 说明改动影响的目标、外观、数值或获得途径 |
| 选择原型、typeID、商店或 scale | 点名实际选择，不得把替玩家决定的内容藏进细节 |

## 方案与 3D 结果

- 方案比较与结果说明使用简短文字列表。
- 玩家必须看形状时，直接展示 Tripo 预览图或实际模型文件。
- 工具未内联显示图片时，必须给出图片路径。
- 预览图、模型文件、编译通过、游戏内加载是不同状态。
- 一张游戏截图只能证明截图里的行为。相关边界必须另行检查。

## 诚实

- 编译通过不等于游戏能加载。
- 游戏能加载不等于目标行为正确。
- 不得报告没有观察过的安装、加载或游戏内行为。
- 工具执行失败与 mod 校验失败必须分开说明。
- 未检查的部分必须直说。
- 玩家未回答时，不得替他决定目标、名字、数值、花费或获得途径。
