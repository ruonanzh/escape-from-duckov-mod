# Duckov 3D 编辑器（`editors/duckov_3d_editor/`）

**玩家 UI**：在文件栏点任意 `.glb`，右侧栏用 **Unity 坐标系**（+Y 上 · +Z 前）打开它。
契约见 [`docs/mod-repo-guide.md`](../../docs/mod-repo-guide.md) §10。

**两个编辑器分工**（契约 v1 只允许读写「打开的那个文件」）：

| 点什么 | 哪个编辑器 | 干什么 |
| --- | --- | --- |
| `.glb` | **本编辑器** | 看模型、调朝向/尺寸/**挂点把手** |
| `config.json` | [`editors/duckov_config_editor/`](../duckov_config_editor/) | 表单改配置，Ctrl+S 保存 |

**挂点数值怎么过去**：本编辑器**显示**出来（可复制），你**抄进另外一个编辑器**。
两者不自动同步。真值在 `config.json`。

## 为什么不照抄游戏的 glb 变换

游戏读 glb 时（`libs/mod-kit/GltfLoader.cs:80-91`）做了四件事：
**顶点 x 取反 · 法线 x 取反 · UV 的 v 取反 · 三角面绕序反转**。

**编辑器不得照做**。踩过坑，记下实测（2026-10-12）：

| 编辑器怎么做 | 正对鸭子时，它的右臂在 | 结论 |
| --- | --- | --- |
| 跟着做一次 X 取反 | 画面**右**侧 | 与游戏左右相反 |
| **不取反** | 画面**左**侧 | 与游戏一致 |

原因：游戏那边那次取反是**坐标系转换**（把 glTF 的右手系换成 Unity 的左手系），
不是显示效果。编辑器里再加上一次，就多翻了一遍。

这个坑只在**不对称模型**上看得出来。枪大多左右对称，所以一直没暴露。

**注意**：这不等于两个模型的坐标可以混用。鸭子 glb 由我们自己的离线管线导出
（`retarget.py`），它的 x 与游戏反向；玩家的武器 glb 是标准 glTF。
因此**落位**时 x 必须单独处理（见「挂点」一节）。

编辑器和游戏**只共用一条规则**（下表）。游戏那边还在做的只剩「按 `front` 声明旋转」
（`ApplyFrontDeclaration`）。长轴摆正与枪口判断（原 `OrientToUnity`、`MuzzleAtPositiveZ`）
已从 kit 里删掉。**编辑器一律不做摆正**。
按 2026-10-12 定调：三类一律不摆正，原点对原点。

| 步骤 | 编辑器 | 游戏 |
| --- | --- | --- |
| 握把归零 | 枪托端起 8%~35% 的**最低点**移到原点（只有「枪」） | `GuessGrip` |

> 游戏仍会摆正。模型产出时若没摆对，**预览会与游戏不一致**。
> 两条出路见设计仓 [`docs/unity-3d-assets/07-duckov-3d-editor.md`](https://github.com/ruonanzh/desktop-gamer-agent-pi/blob/main/docs/unity-3d-assets/07-duckov-3d-editor.md)。

## 界面

- 左上：标题 · 视角按钮（3/4 · 前 +Z · 右 +X · 上 +Y · 后 −Z）· 坐标系说明
- **右下：「物品」**（玩家要调的东西都在这）
  - **类型**：**枪** · 近战 · 物品
  - **握把归零**：只有**枪**才出现（`GuessGrip` 的假设只对枪成立）
  - **尺寸**：填目标「最长边（米）」，等比缩放（配合 `config.json` 的 `size`）
- **常开、不给开关**：**网格**（每格 10cm）
- 面板最下一行是**顶点 / 三角面**（诊断用）
- **原点白十字（±3.5cm）** = 枪的 0 点要对齐的地方
- **玩家鸭**：常驻参照物，站在地面。类型 = 枪 时，模型会被移到它拿枪的
  `Hand.R/MeleeWeaponSocket` 上（游戏里的挂接关系）

## 挂点

面板一栏「挂点」，**只有 枪 / 近战** 显示（游戏侧只有那条路读 `slots.pivot`）。

- **`pivot`（米）**：模型上「哪个点要落到鸭子手上」，相对**模型自身原点**的偏移。
  `0 0 0` = 模型原点就到手上（默认）。
- **坐标顺序处处一致**：面板的三个框、`config.json` 的 `slots`、glb，
  都是 **`[x, y, z]`**（米）。
  `x` 沿 X（左右）· `y` 沿 Y（上下）· `z` 沿 Z（前后 / 枪口方向）。
  因此**看到的就是写进去的**，不用换算。
- **自动猜握把**：只有**枪**显示。等于游戏的 `zeroGrip` 参数
  （`GltfLoader.Load`）。武器默认跑 `GuessGrip`，物品/装备固定不跑。
- **落位公式**：

  | 类型 | 落到哪里 |
  | --- | --- |
  | 枪 | 手部 socket + auto guess grip + pivot |
  | 近战 | 手部 socket + pivot |
  | 物品 / 装备 | 手部 socket（游戏那边按包围盒中心自动对齐，没有 pivot）|

  即 `state.root.position = socket − pivot`，其中 **`x` 分量用加号**。
  鸭子 glb 的 x 与游戏反向（见上），落位时补回来，屏幕上移动的方向才和游戏一致。
  改数字就是**模型动**，不是拖把手。
- **场景里的点**：橙 = 手部（模型对齐到这）· 紫 = 头盔 · 绿 = 护甲 · 蓝 = 背包。
  后三个是**参照物**，只画标记，不做对齐逻辑。

## 配件挂点（只有枪）

「挂点」标题右边有一个模式按钮：

| 模式 | 按钮文字 | 面板 | 类型下拉 |
| --- | --- | --- | --- |
| 物体挂点（默认）| `配件挂点` | `pivot` 行 + 自动猜握把 + 尺寸栏 | 可改 |
| 配件挂点 | `物体挂点` | 上面三项收起，换成 5 行配件挂点 | **禁用** |

- 按钮**只在「类型 = 枪」时出现**。
- 配件模式下**类型下拉禁用** —— 要先切回 `物体挂点` 才能换类型。
- 切模式**只改显示，不清值**：`pivot`、尺寸、自动猜握把都保留。

### 5 个配件挂点是什么

`slots` 里的 `scope`、`muzzle`、`stock`、`grip`、`tec`。

**值的含义**：游戏里**我们模型局部空间**里的一个点（米）。
游戏侧 `WeaponModel.Apply` 会 `socket.position = 我们模型.TransformPoint(值)`，
所以这就是「这个配件要落在我们模型的哪个点上」。

| 轴 | 方向 |
| --- | --- |
| `x` | 沿我们模型的 **X**（左右）|
| `y` | 沿我们模型的 **Y**（上下）|
| `z` | 沿我们模型的 **Z**（+Z = 枪口方向）|

- 游戏里没有的槽位**什么都不发生**（kit 找不到那个挂点就跳过），不报错。
- **我们不创建挂点** —— 游戏只在装了对应配件时才建。
- 打开编辑器时，5 个值按**我们模型的包围盒**算一个启发式默认值（枪口在 +Z 端、
  枪托在 −Z 端、瞄具在顶、握把在下、科技件在侧面）。玩家在面板里改。

### 场景里的简易配件

切到配件模式后，场景里出现 5 个简易网格（圆柱 / 长方体），
按面板里的值摆在模型上。**它们只是视觉参考**，不会进游戏。

- 形状：枪口 = 圆柱沿 Z · 瞄具 = 顶部横向圆柱 · 枪托 = 长方体 ·
  握把 = 圆柱 · 科技件 = 小块。
- **尺寸固定**，不跟着模型的缩放变（游戏里挂点只改位置，不改配件的 scale）。
- 位置**只在两处重算**：`build()` 末尾、改输入框时。**没有每帧循环**。

## 材质与光照（「像不像游戏」和「好不好看」都在这）

- **材质只用 baseColor + 法线**：金属/光泽**贴图一律丢掉**。
  游戏那边 `GameApi.ApplyOurTexture` 明写着把 `_MetallicGlossMap` / `_SpecGlossMap`
  清成 `null`，所以 glTF 自带的 ORM 贴图**游戏根本不用**。
- **metalness / roughness 用常数**（`MAT`）：`0.3 / 0.6`（用户选定）。
  调试可用 URL `?mr=0.6,0.4`。
  「银」只能靠 metalness 表现。设成 0 会让银色件变**白灰**。
  游戏那个值**不是常数**：`BorrowMaterial()` 从**场上第一个用 `SodaCraft/SodaLit`
  的材质克隆**而来，离线无法精确复现。
- **自建摄影棚环境贴图**（`buildStudioEnv`）：深色底 + 顶柔光/侧暖光/背冷光。
  金属面出现**渐变反射与高光条**。
  用 three 自带的 `RoomEnvironment`（全白房间）会把金属**洗白**。
- **三点光**：key · fill（偏冷）· rim（勾轮廓）+ `ambient` 只兜底。
- **不开阴影**（用户：「影子没必要」）。`shadowMap` 关闭，无 `castShadow`／阴影地面。
  只靠明暗与轮廓。

## 技术要点（改之前先看这几条）

- **离线**：宿主 CSP 是 `connect-src 'none'`，**不得走 CDN**。
  `three.bundle.js` 是 vendored 的（esbuild 打包）。
- **`delete window.createImageBitmap`**：three 默认用 `ImageBitmapLoader`
  （`fetch` 读 `blob:`），会被 CSP 挡，于是贴图全丢、看着像「模型没材质」。
  删掉它，three 退回 `<img src=blob:>`（走 `img-src`）。
- **读文件**走桥：依次发 `editor:ready`、`editor:init`、`editor:readFile`，
  宿主回 `editor:fileContent`（base64）。
- **量长轴前必须清零所有变换**。否则读到的是「上一次摆好之后」的包围盒，
  长轴会在每次重算时来回翻。
- **开关顺序**（从外到内）：先 `root` 缩放。再 `mirror`（现为恒等）。
  然后 `grip` 归零。接着 `flip` 把枪口转 180 度。然后 `orient` 按 `front` 旋转。
  最后 `stage` 原模型。
- 模式是 **`edit`**：可调数值，并用「把结果发给 agent」按钮把结果发出去。
  `readScope: siblings` 允许读同目录的 `config.json`。
- **`config.json` 只在打开时读一次**。agent 写盘、config 编辑器存盘之后，
  面板**不会自己变**。要看新的就点标题旁的 **`重新读取`**。
  **不自动轮询** —— 那会把玩家正在调的值冲掉。
- `config.json` 里的 `size` 会**填进输入框**（和 `pivot` / 5 个槽位一样）。
  文件里没写 `size` 时，框里留的是**模型自己的边长**。
