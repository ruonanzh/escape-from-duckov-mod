# ItemModelSwap —— 替换**物品**的模型（示例 mod）

把**一件（或一批）物品**在游戏里的**模型**换成你给的 GLB。
（背包 / 防弹衣 / 头盔 / 面罩 / 耳机 / 弹匣 / 任务道具 / 甚至"本来只有一张图"的消耗品 ✓ —— 任何 `Item` ✓）


## 1. 快速上手（三步 ✓）

```
① 把模型文件放进这个目录（例：backpack.glb）      ← 模型要按**实物尺寸**（背包 ≈ 0.4 m ✓ 头盔 ≈ 0.3 m ✓）
② 改 config.json：指到那件物品                    ← 建议用 `typeIDs`（精确 ✓ 不受本地化影响 ✓）
③ 装机、进游戏：那件物品就是你给的模型了 ✓
```

```json
{ "typeIDs": [36], "model": "backpack.glb" }
```

## 2. 三个"层" + 两个开关 ✓（这是本能力的核心模型 ✓）

```
① **世界**（地上 / 展示 / 穿在身上）      ← `world`（**默认开** ✓）—— 纯外观 ✓ 不改行为 ✓
② **拿在手里**（手里 / 装备）              ← `handheld`（**默认关** ✓）—— ⚠️ **会改行为** ✓
③ **2D 图标**（游戏自带：背包格子 ✓ UI 里那张图 ✓）  ← 我们**从不删** ✓ 但可以替换 ✓
```
- `world` ✓：把那件物品在世界里**画什么**换成你的模型 ✓（这是绝大多数需求 ✓）
- `handheld` ✓：把"拿在手里"那条也换 ✓ —— ⚠️ **副作用**：物品会变得**可以拿在手里 + 能在 UI 里选中** ✓
  （**默认关** ✓ 是有意的 ✓：这是**行为改变** ✗ 不是纯外观 ✓ → 想开就跟玩家确认一句 ✓）
- 第 ③ 层（UI 里那张图）**不属于本能力** ✗ → 想换它要走**图标**那条（见 `docs/` 的图标能力 ✓）

## 3. config.json 字段（一条规则一份 ✓）

| 字段 | 默认 | 说明 |
|---|---|---|
| `world` | **开** ✓ | 换**世界里的模型** ✓（地上/展示/穿戴着 ✓）|
| `handheld` | **关** ✓ | 连**拿在手里**那条也换 ✓ ⚠️ 会改行为（可拿 + UI 可选中）✓ |
| `targets` | — | 物品**对象名全等**（数组 ✓ 不区分大小写；例 `["Item_BackpackLV3"]` ✓ 写错一个字符就不命中 ✗）|
| `typeIDs` | — | 或按 typeID（数组 ✓ 例 `[36, 38]`）—— **推荐 ✓**（更稳 ✓ 不受本地化影响 ✓）|
| `model` | — | 放在本 mod 目录里的 GLB（相对名或绝对路径 ✓）|
| `front` | `auto` | 仅**自带模型**需要：`auto`/`+z`/`-z`/`+x`/`-x` 声明朝向（Tripo 出的靠提示词保证 ✓）|
| ~~`grip`~~ | — | ❌ **已去掉**：物品**不做**"握把归零"✗（那是**枪**的规则 —— `GuessGrip` 假设"枪口 +Z ⇒ 枪托在 −Z"）。而且这条路本来就按**包围盒中心**对齐 ⇒ 归零会被抵消（做了≈没做）✓。位置由对齐决定 ✓；要精调用 `pivot`（属枪那条路 ✓）|

`targets` 与 `typeIDs` **任一命中即可** ✓（可同时给 ✓）；两个都不给 = 这条规则无效 ✗。

**要换多件物品** ✓ 两种写法 ✓：

```json
// ① 一套素材换一件（最常用 ✓）
{ "typeIDs": [36], "model": "backpack.glb", "world": true }

// ② 每件物品各换各的（多条规则 ✓ 按数组顺序匹配，**先命中的生效** ✓）
{ "entries": [
    { "typeIDs": [260], "model": "backpack.glb" },
    { "targets": ["Item_BackpackLV3"], "model": "backpack_lv3.glb", "handheld": true } ] }
```

> ⚠️ 给了 `entries` 就**只看 entries**（扁平字段被忽略）；两者不要混用 ✗

**查物品名 / typeID** ✓：
- `docs/data/Items.csv`（`对象名, 英文名, 中文名` ✓ 例 `Item_BackpackLV1`）
- 或 `inspect_game_data`（`class=Item` / `name=…` ✓ 拿 typeID 用这个 ✓）

## 4. 运行时会做什么 ✓（按物品"有没有 3D 图形"分两条路 ✓）

### 路 A ✓：物品**本来就有** 3D 图形（背包 ✓ 防弹衣 ✓ 头盔 ✓ 面罩 ✓ 耳机 ✓ 弹匣 ✓ …）

```
**就地改**游戏自己那份图形 ✓：
  ① 关掉它原来画的 ✓（不限渲染器类型 ✓ 精灵也关 ✓）
  ② 把我们的 mesh 挂上去 ✓（借游戏自己的材质 ✓ 中心对齐到旧外观的位置 ✓ 缩放补回世界尺度 1 ✓）
  ③ 清实体缓存 ✓ → 游戏下次建实体时读的就是改过的图形 ✓
✓ 为什么最稳 ✓：引用一直是游戏自己那个对象 ✓ → **关卡重建也冲不掉** ✓
✓ **不需要任何挂点配置** ✓ —— "穿在哪/拿在哪"由游戏按角色骨骼自己摆 ✓（背包实测 ✓）
```

### 路 B ✓：物品**没有** 3D 图形（糖果那类"平时只画一张 2D 图"的）

```
**克隆物品预制体 → 注册动态条目** ✓：
  ① `Instantiate` 它自己的物品预制体 ✓（数值 / 图标 / 插槽全部继承 ✓ 只改图形 ✓）
  ② 给它一份图形（原件有就**克隆** ✓ 没有就造一个 ✓ —— 无论哪种都**绝不动游戏原件** ✓）
  ③ `useSpriteForPickup = false` ✓（地上那条改走模型 ✓）
  ④ **`ItemAssetsCollection.AddDynamicEntry(克隆)`** ✓ ← **同一个 typeID** ✓ **遮蔽**原物品 ✓
  ⑤ 对**当前那颗实例**也补写一次 ✓（玩家手里那颗是改动前就存在的 ✗ 动态条目管不到 ✓）
✓ 为什么必须这样 ✓：往**实例**写引用会被**关卡重建冲掉** ✗（实测 ✓）
   而游戏查物品时**先查动态表** ✓ 且动态表是**游戏自己持有的运行时字典** ✓ → 冲不掉 ✓
⚠️ 游戏会打一条警告 ✓：`Dynamic Item Type ID collides with the main game. This will override the main game's item.`
   —— 这是**允许**的用法 ✓（游戏自己留的口子 ✓）不是错误 ✓
```

## 5. 作者要知道的坑 ✓（都踩过 ✓ 代码注释里也写着 ✓）

```
✗ 别把"克隆出来的图形"塞进 DontDestroyOnLoad 再写回 item.ItemGraphic
     → 之后每个实例都生在 DDOL 场景 → **整件物品连原外观一起消失** ✗
✗ 别把图形/agent 挂在**物品下面** → 物品到哪就渲染到哪 → "**一把枪跟着玩家/跟着糖果掉地上**" ✗
✗ 造出来的图形 / agent **模板**要挪到世界外（`y = -5000` ✓）→ 否则**载入画面里看到游离的模型** ✗
✗ 注册动态条目后要**跳过自己的克隆** ✓（`ModelKit_item_*`）+ 同一 typeID **只注册一次** ✓
     → 否则"克隆 → 又被扫到 → 再克隆" → **无限增长卡死** ✗（实测 ✓）
✗ 别每帧扫全场景物品 ✗（`FindObjectsOfTypeAll<Item>` 很贵 ✓）→ 节流 ✓
✗ 造出来的 `ItemGraphicInfo` 字段是 null ✗ → 游戏 `Setup` 会空引用 → 图形用不了 ✓（要补齐 sockets/groundPoints… ✓）
✗ 借不到游戏材质时 Unity 会用默认材质 = **粉色** ✗ → 借"任意一个游戏网格材质" ✓
```

## 6. 做不到 / 还没做 ✓（别承诺 ✗）

| | |
|---|---|
| **UI 里那张图**（背包格子 ✓ "使用时"出现的图 ✓）| ✗ 不是本能力 —— 那是 **UI 画的**（`Duckov.UI.UsageUtilitiesDisplay`）→ 想变只能**改图标**（另一条能力 ✓）|
| **per-item 的尺寸/偏移微调** | ✗ 还没做（目前只有 `front` 声明朝向 ✓）；某件模型明显偏大/偏位时再加 `scale` / `offset` ✓ |
| **改数值 / 改功能** | ✗ 不属于本能力（只换外观 ✓）|

## 7. 验收 ✓

```
· 日志 ✓： [ItemModel] 已换：'Item_BackpackLV1'(typeID=36) ← backpack.glb｜关旧外观 N 个｜挂到 '…'｜…
          路 B 会写：…｜没有 ItemGraphic → **克隆物品预制体 + 注册动态条目**（遮蔽原物品 ✓ 关卡重建冲不掉 ✓）｜…
          没成会写： [ItemModel] 跳过：'…' <原因> ✓
· 游戏里 ✓：地上 ✓ / 穿戴 ✓ / 手里（`handheld` 开了才有 ✓）变成你的模型 ✓
⚠️ **要让它重新实例化一次才看得到** ✓：丢地上再捡 / 换下来再穿上 / 重进关卡 ✓
   （物品的实体会被游戏缓存 ✓ 这是游戏行为 ✓ 不是 mod 的问题 ✓）
```

## 8. 改完不用重启 ✓

`config.json` **存盘即生效** ✓（mod 每 0.25 秒查一次写入时间 ✓）；改完会先**还原**旧结果再重挂 ✓
（所以从"变成枪"改回原样，也只要把那条规则删掉 / 改成别的 ✓）。
