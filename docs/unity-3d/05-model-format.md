# 05 · 模型格式（零件清单 JSON）

做**物品 / 武器 / 配件 / 建筑**的模型时，写这种 JSON：一份**零件清单**，运行时由库生成 mesh 并挂上去。
模型文件放 mod 目录，玩家可自己改参数。角色用 YSM（见 [`03-characters.md`](03-characters.md)）。

## 长什么样（骨架）

```json
{
  "name": "parts_skeleton",
  "category": "weapons/other",
  "summary": "骨架：字段怎么摆",
  "parts": [
    { "role": "body", "shape": "box", "size": [0.030, 0.032, 0.170], "at": [0, 0.030, 0.005] }
  ],
  "slots": {
    "Scope":  [0, -0.005, -0.038],
    "Tec":    [0, -0.005, -0.09],
    "Muzzle": [0, -0.035, 0.19],
    "Stock":  [0, -0.07, -0.35],
    "Grip":   [0, -0.095, 0.03]
  },
  "material": { "mode": "clone", "pick": "body" },
  "texture": {
    "size": [256, 256],
    "pixels_per_meter": 512,
    "source": "generated",
    "fills": { "body": "#3A3F44" }
  },
  "attach": { "kind": "item_graphic" }
}
```

**完整例子在各类别文档里**：[`01-weapons.md`](01-weapons.md) · [`02-items.md`](02-items.md) · [`03-characters.md`](03-characters.md)（YSM）· [`04-buildings.md`](04-buildings.md)。

## 字段

### 顶层

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 模型名（与文件名一致，小写下划线）|
| `category` | ✅ | `weapons/*`（`Weapon`/`Gun`）· `melee/*`（`MeleeWeapon`）· `accessories/*`（`Accessory`：muzzle/scope/grip/stock/magazine）· `items/*` · `buildings/*` —— 与游戏的 `Item.tags` 分类一致 |
| `summary` | | 一句话：这是什么、由哪些部分组成 |
| `parts[]` | ✅ | 零件清单（见下）|
| `material` | | `{"mode":"clone","pick":"body"}` = 克隆游戏里同类的现有材质（URP 自定义 shader 必须克隆）|
| `texture` | | 贴图与 UV（见「贴图与 UV」一节）：尺寸、texel 密度、来源、每零件底色 |
| `slots` | | 可选，配件挂点：`{"<槽位>": [x,y,z] \| null}`（米、**模型坐标系**；`null` = 没有这个挂点）。**多数模型不用写** —— 不写则运行时按零件语义自动摆；取值方法见 [`01-weapons.md`](01-weapons.md) 的「槽位」一节 |
| `attach` | | `{"kind":"item_graphic"}`（物品）/ `{"kind":"socket","name":"HelmatSocket"}`（挂饰）|
| `pivotOffset` | | 可选，`[x,y,z]`（米）—— 模型原点的微调；默认零即"模型自己的原点"|

### `parts[]` 每个零件

| 字段 | 说明 |
|---|---|
| `role` | 这个零件是什么（`slide`/`barrel`/`grip`…）—— 便于对照与后续替换 |
| `shape` | `box` · `cylinder` · `cone` · `sphere` · `lathe` · `extrude` |
| `size` | `box` 用：`[宽, 高, 长]`（米）|
| `r` / `r1` / `r2` | `cylinder` 半径 / `cone` 底半径、顶半径 |
| `h` / `depth` | 高 / 拉伸厚度（米）|
| `segments` | 圆周分段（圆柱/圆锥/球/旋转体；常用 12–24）|
| `profile` | `lathe` 用：`[[半径, 高度], …]` 轮廓点 |
| `outline` | `extrude` 用：`[[x, y], …]` 二维轮廓 |
| `at` | 位置 `[x, y, z]`（米），相对模型原点 |
| `rot` | 旋转 `[x, y, z]`（度，等价 `Quaternion.Euler`）|
| `scale` | 可选，`[x, y, z]`（默认 1）|
| `mirror` | 可选，`"x"` — 该零件再镜像生成一份（左右对称的物件只写一边；游戏中武器 mesh 多数以 `x = 0` 为中心，如 `WPN_*` 里 113 个有 68 个 `center.x ≤ 5mm`）|

## 约定

- **单位 = 米**；物品模型大致 **0.1–1 m**。
- **坐标**：`+Z` 朝前（枪口 / 正面）、`+Y` 朝上。
- **原点 = 游戏放置点**：手持时它就是**手握住的地方**（武器 = 握把中心）；掉落时游戏按图形 prefab 的 `groundPoint` 贴地，所以物品类把原点放在"底部中心"最省事。
- **尺寸 = 真实米制，`scale` 恒为 1 —— 运行时永不缩放。** 这是实测标准，不是约定俗成：
  | 来源 | `scale = 1` 的比例 |
  |---|---|
  | 原游戏全部 Transform（14192）| 83.8% |
  | **原游戏物品图形 `IG_*`（371）** | **99.5%** |
  | 社区 mod 的包（优香MPX 26 / 三角洲合集 200）| **100%** |
  → 新模型自己定义大小（枪 0.5–0.9 m、手枪 0.17–0.21 m…），**不要用缩放去凑**原来的模型。
- **几何一律由参数算出**（顶点/索引/UV/法线由库生成），不写死顶点。
- **多零件可共用一张 mesh**；要分色就分 submesh（按 `role` 分组）。
- **尺寸上限 10 m**（游戏里最大的资产是 6 m）—— 超了基本是单位写错。
- **贴合游戏**见 [`00-shared.md`](00-shared.md)（`groundPoint` / sockets / 层 / 材质）。

## 两个"画不出来"的坑（工具会拦）

| 坑 | 现象 | 规则 |
|---|---|---|
| **绕序反了** | 模型**完全看不见**（只剩游戏原版的部件），控制台无报错 | Unity 是**左手系**：从外侧看**顺时针**才是正面。右手叉积应指向法线的**反方向** |
| **法线没跟着零件旋转** | 旋转过的零件不受光/发黑（其余正常） | 顶点做旋转后，**法线也要按同一旋转**变换（法线的正确变换是"逆转置"；轴对齐缩放就除以缩放） |

两条都是库内部（`MeshKit`）的约定 —— 自己写生成代码时照做即可；`model-check` 会按绕序直接 FAIL。

## 贴图与 UV

**一张 base color 贴图就够** —— 不做 法线 / 金属 / 粗糙 贴图（游戏本体的物品资产也没有，社区 mod 里也没见到：实测 67 件收藏品全是单张 `*_basecolor`）。贴图宽高都取 2 的幂（128 / 256 / 512）。

### 物品类（零件清单）：UV 由工具按 box-UV 自动排布

作者**不写 UV** —— 工具按下面规则算，运行时库用**同一套规则**，所以两边一定一致：

1. **texel 密度**：`pixels_per_meter`，**可以省略** —— 不写时工具自动取「能塞进 `size` 的**最大**密度」，并把结果按「mm / 像素」打出来。
2. **每个 box 的展开矩形**（像素）：`宽 = 2·d + 2·w`，`高 = d + h`（`w/h/d` = 该零件的尺寸换算成像素）。
3. **摆放**：按 `parts` 顺序**从左到右、一行一行**放；行高 = 该行最高零件的展开高，放不下就换行。
4. **每个面在矩形里的落点**（box-UV 标准摆法，`uv` = 矩形左上角）：

   ```
                u       u+d      u+d+w    u+2d+w   u+2d+2w
       v        ┌────────┬────────┬────────┬────────┐
                │  top   │ bottom │        │        │   top / bottom：w × d
       v+d      ├────────┼────────┼────────┼────────┤
                │ right  │ front  │  left  │  back  │   侧面/正背面：d×h / w×h
       v+d+h    └────────┴────────┴────────┴────────┘
   ```

5. **装不下就报错**（提示加大 `size` 或调小 `pixels_per_meter`），不静默裁掉。

**默认贴图 `"size": [512, 512]`。** 自动密度实测（本文档里的样例）：

| 模型 | 512² 下的自动密度 | 每像素 |
|---|---|---|
| 手枪 / 消音器 / 铁锤 | 420 / 1024 / 512 px/m | 2.4 / 1.0 / 2.0 mm |
| 冲锋枪 / 步枪 | 331 / 252 px/m | 3.0 / 4.0 mm |
| 罐头 / 手办 / 背包 / 头盔 / 防弹衣 / 储物箱 | 635 / 249 / 136 / 137 / 109 / 89 px/m | 1.6 – 11 mm |
| 柱子 | 121 px/m | 8.3 mm |
| 自助机器 / 墙 / 地板 | 32 / 26 / 13 px/m | 31 / 39 / 77 mm |

→ **小物件**（0.1–0.5 m）密度够细，能画面板线、迷彩；**建筑**（米级）密度粗（每像素 3–8 cm），适合纯色与大色块（要更细就上 1024²）。

### 角色（YSM）：UV 写在模型里

cube 的 `uv` 是**像素坐标**，指向 `textures/` 里的皮肤图；贴图尺寸由 `description.texture_width/height` 声明（实测某 YSM 模型 = 512×512 + 497 个 cube）。**同一套 box-UV 规则**，只是坐标由作者/生成器写死。

### 贴图从哪来（两条，都不需要 Unity）

| 来源 | 写法 | 说明 |
|---|---|---|
| **程序化生成**（主路）| `"source": "generated"` + `"fills": {"<role>": "#RRGGBB"}` | 工具按排布往每个面填色；`fills` 少的零件可用一个默认色。图案（条纹/迷彩/面板线）后续再加字段 |
| **整张图**（手绘 / 外部图）| `"source": {"file": "textures/gun.png"}` | 图的尺寸必须等于 `size`。工具可**导出 UV 模板**（在每块上标出"哪个零件的哪个面"），照着涂 |

### 校验（工具按这些判）

- 所有展开矩形都在贴图内、**互不重叠**；
- `size` ≥ 实际需要；`pixels_per_meter` > 0；
- 给了 `file` 时：图片尺寸 == `size`；
- 顶点数远超同类量级时提示（游戏本体中位 402 顶点）；
- 自动密度低于 32 px/m（即每像素 > 3 cm）时提示"这套贴图只够大色块"。

## 零件与三角面数（低多边形风格的对齐参考）

| 形状 | 顶点 | 三角面 |
|---|---|---|
| `box` | 24 | 12 |
| `cylinder`（n 段，含两端盖）| 10n | 4n |
| `cone`（n 段，尖端）| 7n | 2n |
| `cone`（n 段，圆台含两端盖）| 10n | 4n |
| `sphere`（经 lon × 纬 lat）| 4·lon·lat | 2·lon·lat |
| `lathe`（n 段 × 轮廓 k 点）| 4·n·(k−1) | 2·n·(k−1) |
| `extrude`（轮廓 m 点）| 10m | 4m |

> 顶点按"每个面独立"计（硬边与 UV 接缝需要），与实现一致；三角面数是确定的。

> 游戏本体 mesh 顶点数**中位数 402**（平均 729，最大 17,594）—— 简单道具**几百到几千顶点**就够贴合画风。
> 物品 prefab 常带多级 LOD（同名 mesh 出现多次）；我们只做**一级**（相当于 LOD0）。
